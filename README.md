# გარდაბნის მობილური აკადემია (ვერსია 0.3 — „ნარსილი“)

ინტერაქტიული ვებ-პლატფორმა და საგანმანათლებლო რუკა გარდაბნის მუნიციპალიტეტის ახალგაზრდებისთვის.

პროექტის მიზანია გარდაბნის მუნიციპალიტეტში ქართველ და აზერბაიჯანელ ახალგაზრდებს შორის კულტურული დიალოგის, ურთიერთთანამშრომლობისა და არაფორმალური განათლების გაძლიერება მობილური აკადემიის მეშვეობით.

🌐 **ვებ-აპლიკაცია:** [https://25blackgiants.github.io/gardabani-mobile-academy/](https://25blackgiants.github.io/gardabani-mobile-academy/)

## ვერსია 0.3 — „ნარსილი“

- სრულად მხარდაჭერილია ქართული და აზერბაიჯანული საჯარო კონტენტი.
- საიტი მუშაობს როგორც დასაყენებელი PWA და ინარჩუნებს ადრე გახსნილ გვერდებს ოფლაინ რეჟიმში.
- დაემატა ავტომატური build და ხარისხის შემოწმება GitHub-ზე.
- კონტენტი, თარგმანები და გენერირებული გვერდები მოწმდება build პროცესში.

## 🌟 პლატფორმის ძირითადი ფუნქციები

* **🗺️ ინტერაქტიული რუკა (Web GIS & Smart Map)**
  * გარდაბნის მუნიციპალიტეტის ოფიციალური საზღვრები და საკვანძო ლოკაციები.
  * ცენტრალური საგანმანათლებლო ჰაბი და მობილური ვორქშოფების სოფლები.
  * რუკის სამი ვიზუალური ფენა: საგზაო (Roadmap), სატელიტური (Satellite) და რელიეფური (Terrain).
  * 🚗 **პირდაპირი ნავიგაცია:** ერთი დაწკაპუნებით Google Maps-ის მარშრუტის გახსნა ნებისმიერ სოფელში მისასვლელად.
  * 🎯 **აქტივობების მენიუ (Drawer):** სოფლების ჩამონათვალი, თარიღები და ლოკაციაზე სწრაფი გადაფრენა რუკაზე.

  * რუკაზე კონკრეტულ წერტილზე პირდაპირი გადასვლა (`?loc={id}`) და ადგილზე მისვლის მარშრუტი.

* **👥 მენტორების კატალოგი**

    * არაფორმალური განათლება და კულტურათაშორისი დიალოგი
    * ახალგაზრდული ინიციატივები და სამოქალაქო აქტივიზმი

    * სოციალური მეწარმეობა და სათემო პროექტები

## ადგილობრივად გაშვება და კონტენტის შეცვლა

პროექტს არ სჭირდება დამატებითი პაკეტების ინსტალაცია. საჭიროა Node.js.

1. ლოკაციების შესაცვლელად დაარედაქტირეთ `src/data/locations.js`, მენტორებისთვის — `src/data/mentors.js`.
2. აზერბაიჯანული საჯარო კონტენტის შესაცვლელად გამოიყენეთ იმავე ID-ებით `src/data/localized_content.js`. build პროცესი ამოწმებს, რომ ყველა ლოკაციასა და მენტორს სრული თარგმანი ჰქონდეს.
3. გაუშვით `node build_map.js` — ეს გადაამოწმებს მონაცემებს და თავიდან შექმნის საჯარო HTML გვერდებს.
4. გაუშვით `node verify.js` — ყველა შემოწმება უნდა დასრულდეს წარმატებით.
5. გახსენით `index.html` ბრაუზერში ან მიაწოდეთ საქაღალდე ნებისმიერი სტატიკური ვებ-სერვერით.

`index.html`, `gardabani_map.html`, `calendar.html`, `mentors.html` და `settings.html` გენერირებული ფაილებია. მათში პირდაპირ შეტანილი ცვლილებები მომდევნო build-ის დროს გადაიწერება, ამიტომ მუდმივი ცვლილებები უნდა გაკეთდეს `build_map.js`-ში ან შესაბამის `src/` მოდულში.

მენტორის ფოტოს დასამატებლად მის ჩანაწერში მიუთითეთ არასავალდებულო `photo` ველი, მაგალითად `photo: "images/mentors/name.webp"`. მხარდაჭერილია `images/` ან `assets/` საქაღალდის უსაფრთხო ლოკალური მისამართები და HTTPS ბმულები. თუ ფოტო მითითებული არ არის ან ვერ ჩაიტვირთა, საიტი ავტომატურად აჩვენებს არსებულ გენერირებულ ავატარს.

## ხარისხი, ოფლაინ რეჟიმი და გამოქვეყნება

- `src/build/generator_utils.js` შეიცავს გენერატორის საერთო, უსაფრთხო სერიალიზაციისა და ფაილების ჩაწერის ლოგიკას; გვერდის შაბლონები კვლავ `build_map.js`-შია, რათა არსებული მუშაობა უცვლელი დარჩეს.
- საიტი არის დასაყენებელი PWA: `manifest.webmanifest`, `service-worker.js` და `offline.html` უზრუნველყოფს ადრე მონახულებული გვერდების ოფლაინ fallback-ს. განახლებისას HTML პირველ რიგში ქსელიდან იტვირთება, ამიტომ გამოქვეყნებული ცვლილებები არ რჩება მოძველებული ქეშის გამო.
- `.github/workflows/quality.yml` ყველა `main` და remediation branch push-ზე თავიდან აგენერირებს გვერდებს, უშვებს `verify.js`-ს და ამოწმებს, რომ გენერირებული HTML commit-შია.
- GitHub Pages-ის არსებული გამოქვეყნება კვლავ `main` branch-ზე push-ის შემდეგ მუშაობს; workflow არ ცვლის Pages-ის ან Supabase-ის კონფიგურაციას.

## უსაფრთხოების საზღვრები

- ადმინისტრატორის gateway და რედაქტირების ინტერფეისი შენარჩუნებულია.
- build პროცესი უარყოფს არასწორ თარიღებს, კოორდინატებს, დუბლირებულ ID-ებს, დაუშვებელ URL-ებსა და ზედმეტად დიდ ტექსტურ ველებს.
- დინამიკური ტექსტი HTML-ში ჩასმამდე იფილტრება, ხოლო სოციალური ბმულები მხოლოდ HTTPS მისამართებს იღებს.
- Supabase-ის მონაცემთა ბაზის პოლიტიკები, authentication პარამეტრები და production მონაცემები ამ build პროცესით არ იცვლება.
- `.env`, გასაღებები, პაროლების ტექსტური ფაილები და მონაცემთა ბაზის dump-ები Git-ში არ უნდა მოხვდეს.
